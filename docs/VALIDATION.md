# Проверка этапа 10

## Контракт Offline / Hold

При обнаружении gap, регресса, конфликтующего дубля, плохого кадра, превышения лимита или разрыва WS адаптер синхронно публикует `Offline` **до ожидания close, backoff или snapshot**. Для ETHUSDT достаточно одного `Offline`, чтобы робот выдавал только `Hold` с `edge_bps = None`. Исправный гейт продолжает обновляться; поток робота продолжает polling и диагностику.

Возобновление bias возможно только после нового snapshot + replay, когда обе книги `Online` и проходят проверки свежести/skew/объёма. Валидный diff сам по себе не отменяет восстановление.

«Сразу» отсчитывается от обнаружения сбоя: робот принимает новый статус на следующем чтении буфера. Уже начатый расчёт использует приобретённые снимки. Молчаливый обрыв обнаруживает watchdog (3 с), а робот переходит в `Hold` раньше по max-age (по умолчанию 500 мс). Triple buffer хранит последнее состояние: краткий `Offline`, полностью прошедший между чтениями, может быть пропущен; причины и счётчики сбоя сохраняются.

## Локальные проверки

58 unit/integration/property-тестов, fmt, Clippy и release-сборка проходят.

Сквозные тесты используют настоящий `service::run`, оба адаптера, опубликованные книги и OS-поток робота:

- `LongBias → Hold → LongBias`: gap, регресс, конфликтующий дубль, malformed, Close, EOF и oversized WS — отдельно для каждой биржи (14 комбинаций).
- Задержанный snapshot, переполнение sync-очереди и поздний отменённый HTTP-ответ оставляют робот в `Hold`.
- Ping и точные дубли не освежают данные: сначала `Hold` по возрасту, затем `Offline` по watchdog.

Существующие проверки покрывают старый parse worker, медленного читателя, пропуск короткого `Offline`, одновременные публикации/deadline, shutdown и сбои workers. Сквозные тесты: `src/md/feed/tests/service_tests.rs`.

| После SIGTERM | `Stopped` | `Stopped` |

Получены 4 решения с обеими книгами `Online`, ценами/объёмами, временными метками и рассчитанным отклонением. Пропущенных публикаций и потерянных логов — 0; exit code — 0, принудительное завершение не потребовалось. Это короткая проверка подключения и жизненного цикла, не измерение latency или длительной стабильности.

Повторить:

```bash
cargo build --release --locked
python3 scripts/public_smoke.py
```

Скрипт включает DEBUG для приложения и ждёт до 45 с готовности обеих книг, собирает ещё 3 с данных и посылает SIGTERM. Сохраняет `events.log` и `summary.json` в новую папку `/tmp/hft-public-smoke-*`; `--output DIR` задаёт новую папку явно. Возвращает ненулевой код, если обе книги не стали `Online` или shutdown не завершился штатно. Нужен доступ к публичной сети; smoke не входит в `cargo test`.

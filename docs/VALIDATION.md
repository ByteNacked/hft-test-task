# Проверки

## Корректность

После рефакторинга 2026-10-22 проходят **33 теста** (было 46), `fmt`, Clippy с `-D warnings` и release-сборка. Сохраняются проверки поведения:

- Точность fixed-point, переполнение, tick/lot, схемы сообщений и лимиты входа.
- Snapshot + diff: bridge, `pu`, дубли/конфликты, повреждение книги и обязательное восстановление.
- Книга против модели `BTreeMap`, границы ценового окна/битовых карт, смена базы, независимый кэш top-20.
- Консистентные публикации, быстрый Offline → Online с обязательным Hold, порог/age/skew/объём сигнала.
- Независимое восстановление фидов при gap, плохих кадрах, disconnect, timeout, overflow и выходе цены за окно; watchdog, устаревший snapshot, shutdown/panic.
- Отложенное форматирование, фильтры логов, время события, переполнение и drain при завершении.

Сквозные тесты используют локальные HTTP/WS-серверы, общий Tokio runtime с двумя workers и [синтетические fixtures](../tests/fixtures/README.md).

```sh
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
cargo build --release --locked
```

## Задержка MD → смена bias

2026-10-22, Intel Core Ultra 9 285HX, release. До/после текущего рефакторинга: два Tokio workers, по task на фид, отдельный busy-loop робот, штатные formatter/writer и INFO-логи. CPU affinity нет. По одному последовательному запуску, 1000 прогревочных и 10 000 измеряемых сообщений на фид, заданная частота 1000 сообщений/с.

Путь: готовый JSON → decode/sequence/update → публикация top-20 → чтение роботом → callback со сменой bias. Сеть, TLS, сборка WS-сообщения и планирование до отметки получения исключены. Отсчёт идёт от более свежей книги решения; в выборке только смены bias. Промежуточные версии могут заменяться. Логирование предыдущих решений влияет на следующие проходы.

Время в **мкс**, глубина на сторону, изменения bid/ask:

| Биржа; глубина; изменения | p50 до → после | p99 | p99.9 | Выборок до → после |
| --- | --- | --- | --- | --- |
| binance; 1000; 2/1 | 2.70 → 2.25 | 10.61 → 9.02 | 15.05 → 13.88 | 9561 → 9509 |
| aster; 1000; 2/1 | 2.72 → 2.27 | 10.24 → 9.08 | 15.38 → 14.63 | 9586 → 9519 |
| binance; 8000; 2/1 | 2.68 → 2.57 | 10.26 → 9.88 | 15.28 → 14.37 | 9519 → 9573 |
| aster; 8000; 2/1 | 2.59 → 2.52 | 10.28 → 9.68 | 15.11 → 13.18 | 9570 → 9572 |

| aster; 1000; 100/100 | 11.48 → 11.38 | 45.69 → 41.90 | 51.74 → 48.84 | 9549 → 9517 |

Во всех сценариях опубликованы все 10 000 сообщений на фид; фактическая частота до/после — около 1000,1 сообщений/с на фид. Это проверка задержки при заданной нагрузке, не максимальной пропускной способности. В этом сравнении квантили не ухудшились; одного запуска без affinity недостаточно для вывода о стабильном ускорении или верхней границе задержки.

```sh
python3 scripts/validate_hotpath.py
```

Скрипт измеряет текущие исходники в отдельной временной копии; `--samples N` задаёт число сообщений (минимум 5000). Для сравнения запускайте его до/после изменения последовательно. Совместимость с историческими API удалена. Результаты: `/tmp/hft-threaded-validation-*/{results.json,stdout.log,events.log}`. Для приведённого сравнения: до — `1i2t0cka`, после — `jq8mywa1`.

## Аллокации

В отдельной release-копии временный allocator-счётчик проверил decode → sequence/update → publish/read → evaluate: **0 alloc/dealloc/realloc** на 10 000 обновлений после прогрева в каждом из шести сочетаний биржи, глубины и размера diff выше. Сообщения и рабочие буферы подготовлены заранее; цены около 6000 проверяют ненулевую базу окна. Аудит однопоточный, не включает сеть/TLS, восстановление, ошибки и фоновые потоки логирования. Инструментация не включена в рабочий код; журнал — `/tmp/hft-cleanup-allocation-5ps_udrx/audit.log`.

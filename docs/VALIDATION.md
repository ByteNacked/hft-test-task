# Проверки

Массивы по шагу цены, triple buffer со счётчиками разрывов и отложенное форматирование INFO/DEBUG робота и фидов: **42 теста**, `cargo fmt --check`, Clippy с `-D warnings` и release-сборка проходят.

Покрытие:

- точный однопроходный парсинг цен/количеств, диапазоны и шаги инструмента; property-проверка представимых raw-значений и переполнения с ведущими/дробными нулями;
- преобразование diff в проверенные индексы, граница массива, неверные tick/lot size, сохранение типа ошибки диапазона и повторное использование буфера после ошибки;
- обе схемы сообщений, ошибочные/повторяющиеся поля и лимиты; повторное использование diff-буферов после частичного разбора, сохранение последнего diff и очистка старых уровней;
- snapshot/bridge, непрерывность `pu`, дубли, конфликт и регрессия;
- update/delete, покрытие и запрет diff/Online после повреждения книги до нового snapshot; property-сверка с `BTreeMap`;
- крайние ячейки, границы слов/групп битовой карты, большие пустые промежутки, удаление занятости и сброс при новом snapshot;
- индекс группы с best bid/ask: улучшение цены, опустошение лучших групп, изменение только объёма, перенос после нового snapshot;
- кэш top-20 с независимым обновлением сторон, изменением на границе, свежими timestamps после глубоких изменений; публикация до 20 лучших уровней каждой стороны, продвижение глубоких уровней после удаления лучших и восстановление более короткой книги;
- стабильность книги при конкурентном чтении, получение последней версии после серии публикаций, Offline/Hold при быстром восстановлении, запрет Online для старых поколений;
- Long/Short/Hold, порог, возраст, skew, объём и Offline любой книги;
- форматирование вне потоков робота и фидов, параллельная отправка из двух фидов с сохранением их порядка и исходного thread ID, сохранение данных/времени события и цветов, INFO/DEBUG-фильтрация, drain при закрытии; переполнение без перезаписи, повтор непринятого bias и ERROR с числом потерь;
- сквозной путь HTTP/WS → книга → робот: gap, malformed, Close, EOF, oversized и цена вне диапазона для обеих площадок;
- задержанный snapshot, Ping/Pong, overflow, старый HTTP-ответ, HTTP timeout и watchdog при дублях;
- отбрасывание устаревшего parse worker, его ожидание при shutdown, явная ошибка при выходе/panic worker.

Сквозные тесты запускают оба адаптера в общем Tokio runtime с двумя workers. Тесты используют локальные HTTP/WS-серверы и синтетические [fixtures](../tests/fixtures/README.md). Исходы проверяются по книге, решениям и восстановлению соединения; тестовых счётчиков в рабочем коде нет.

## MD → смена bias: рабочая схема потоков

**2026-10-22, Intel Core Ultra 9 285HX, release.** Вместо однопоточного микрозамера используется общий Tokio runtime с **двумя workers**, две независимые задачи фидов, отдельный OS-поток busy-loop робота и штатный поток записи логов. Supervisor работает в вызывающем потоке. INFO-логирование смен bias включено; вывод направлен в файл. Задачи могут мигрировать между workers, закрепления за CPU нет. `max_blocking_threads(2)` совпадает с сервисом, но загрузка snapshot в этот steady-state замер не входит.

Измеряемый путь: отметка получения готового JSON → штатные decode/sequence/update → публикация лучших 20 уровней → чтение в другом потоке → расчёт и вход в callback со сменой bias. Используются `Runner::apply`, `service::run`, `Robot` и `decision_reporter` из измеряемой версии. Сеть, TLS, сборка WS-сообщения и ожидание запуска задачи **до** отметки получения исключены. Текущая запись лога начинается после конечной отметки; обработка предыдущих логов влияет на последующие решения.

Каждый фид получает 1000 прогревочных и 10 000 измеряемых сообщений с заданной частотой **1000 сообщений/с**. Фиды не ждут робота. Цены чередуются, вызывая реальные LongBiasAster/ShortBiasAster/Hold. В выборку входят только смены bias; отсчёт — от получения более свежего из двух сообщений, книги которых использованы решением. Количество таких выборок не равно количеству публикаций: не каждый апдейт меняет bias, а промежуточные версии могут заменяться.

## Удаление rollback

После невалидного результата diff книга требует новый snapshot: последующие diff и публикация Online запрещены, адаптер публикует Offline. Удалены сохранение прежних количеств и 64 KiB буферов на фид. Тесты проверяют неизменность уже опубликованной версии, запрет повторного старого diff и восстановление после нового snapshot.

Release A/B относительно варианта с кэшем top-20 и rollback: три пары с чередованием порядка, тот же однопоточный harness, 1000 прогревочных + 10 000 измеряемых сообщений. Медианы показателей для Binance, глубина 1000; время — нс, throughput — млн сообщений/с цикла.

| Глубокие уровни обеих сторон | 461 → 460 | 510 → 492 | 683 → 725 | 1,95 → 2,01 |

Повторный аудит обоих декодеров, глубин 1000/8000 и этих сценариев: **0 alloc/dealloc/realloc** на участке decode → update → publish/read → evaluate и отдельно при отклонении пересечённой книги. Инструментация аллокатора остаётся только во временных копиях.

## Аллокации

Отдельный release-аудит через обёртку `System` с thread-local счётчиками, повторённый после изменения парсера и индексов: **0 alloc/realloc/dealloc** на участке JSON → decode/sequence → update → publish → evaluate, включая последующий rollback пересечённой книги. Проверены оба декодера, глубины 1000/8000, diff 2/1 и 100/100, по 1000 сообщений на сочетание. Инструментация добавлялась только во временную копию проекта; рабочий код сохраняет запрет `unsafe`.

Это однопоточный аудит без WS/TLS и логирования; JSON и все буферы готовятся до включения счётчиков. Его результат нельзя переносить на весь сервис, обработку ошибок с логами или любые произвольные JSON. В обычной обработке diff массивы не расширяются. Полная очистка массивов выполняется только при загрузке snapshot; этот этап не входит в замер задержки.

## Ограничения

Offline публикуется после обнаружения сбоя до ожидания восстановления. Начатый расчёт использует уже приобретённые версии. Offline доставляется через статический счётчик поколения независимо от замены промежуточных публикаций; до приёма новой Online-версии робот обрабатывает Offline. Старые поколения отбрасываются. Робот получает последнюю опубликованную книгу, без накопления очереди и ошибок заполнения. Молчание обнаруживается watchdog, а устаревание — проверкой возраста в роботе. Очередь логов ограничена и при переполнении может отбрасывать записи.
